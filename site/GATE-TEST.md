# Gate test passed — the token pipeline is viable

Verified 2026-09-16, before any real UI was written.

## The question

Can the site get Loom's design tokens by `@import`ing a generated stylesheet,
or must the token regions be concatenated directly into `globals.css`?

This matters because the app's tokens are not plain CSS variables. They are
Tailwind v4 *directives* — `@utility rounded-window { … }`, `@theme`,
`@custom-variant dark` — and Tailwind processes them at build time. If Tailwind
does not inline an `@import`ed sheet before resolving its own directives, the
utilities the entire app is built from would simply not exist in the site's
stylesheet, and every component copied from the app would render unstyled.

## Method

`src/app/_gate-test.css` was imported by `globals.css`, declaring one of each
construct, and `src/app/page.tsx` rendered one element per class. Then
`_gate-check.mjs` grepped the **emitted** CSS — not the build log, which would
have passed either way.

## Result: every construct survived

| # | Construct | Emitted |
| --- | --- | --- |
| 1 | `@custom-variant dark (&:where(.dark, .dark *))` | `:where(.dark` present |
| 2 | `@theme { --color-gate-accent }` | `.bg-gate-accent` auto-generated |
| 3 | `@utility rounded-window` + `var(--radius-window)` | rule present |
| 4 | `corner-shape: squircle` (Chromium-only) | passed through verbatim |
| 5 | `@utility gate-panel` (plain block) | rule present |
| 6 | `@utility text-soft` + nested `&:hover` | rule + `.text-soft:hover` |
| 7 | `@utility gate-focus` + nested `&:focus-visible` | rule + pseudo-class rule |
| 8 | `@keyframes` + hand-written `.animate-*` class | both present |

`VERDICT: the token pipeline is viable — @utility, @theme and @custom-variant
all survive an @import'ed sheet.`

## Consequences

1. `scripts/sync-site-tokens.mjs` can extract the marked regions of
   `src/styles.css` verbatim into `site/src/app/loom-tokens.css`, and
   `globals.css` just imports it. No rewriting, no concatenation, no
   duplication of Tailwind's work.
2. Because the utilities are generated by the same Tailwind version from the
   same source, the site and the app cannot drift in *behaviour* — only in
   content, which the CI parity check covers.
3. `corner-shape: squircle` reaches the browser unmodified, so the site gets
   the app's continuous corners in Chromium and degrades to a plain radius
   elsewhere, exactly as the app does.
