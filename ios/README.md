# ios

Swift and SwiftUI: the iPhone app, in one Xcode project generated from a spec with [XcodeGen](https://github.com/yonaskolb/XcodeGen) rather than a hand-edited `.xcodeproj`. It links the same [core](../core/) as the desktop app, and does less than the desktop where that suits a phone. Its widgets, Live Activities and push extension join the same project later.

The app holds no logic (PLAN.md, "The apps hold no logic"). It draws screens and reaches the system: the camera, photos, files, notifications, the clipboard. Everything else is the core's, which it talks to only in JSON, through `loom_core_start`, `loom_core_send` and `loom_core_stop` ([core/README.md](../core/README.md#between-the-app-and-the-core)).

## Building it

On a Mac with Xcode and XcodeGen (`brew install xcodegen`), from the repository's root:

```sh
calx scripts/ios.calx           # the core for a phone and the simulator, then ios/Loom.xcodeproj
calx scripts/ios.calx --sim     # the core for the simulator alone, which builds faster
calx scripts/ios.calx --sample  # no core: the project alone, with the app on sample frames
open ios/Loom.xcodeproj
```

[`scripts/ios.calx`](../scripts/ios.calx) builds `core/lib.calx` with `calx build --staticlib --target aarch64-ios` and `aarch64-ios-sim`, gives `loomcore.h` a module map so Swift imports it as `LoomCore`, puts both in `build/ios/LoomCore.xcframework`, and runs `xcodegen` with `LOOM_CORE=YES`, which includes [`core.yml`](core.yml) to link it. `Loom.xcodeproj` isn't kept in git: change [`project.yml`](project.yml) and run the script again.

The app icon is the one [`scripts/icons.calx`](../scripts/icons.calx) makes, [`design/logo/ios/AppIcon.appiconset`](../design/logo/ios/AppIcon.appiconset), light, dark and tinted. Xcode's asset compiler doesn't follow links, so the script copies it into `build/ios/Icons.xcassets` each time, `--sample` too, and the project takes it from there.

Emoji are drawn with [Twemoji](https://github.com/jdecked/twemoji), not the system's emoji font ([PLAN.md, "Emoji"](../PLAN.md#emoji)). The script puts each SVG in [`design/twemoji/svg`](../design/twemoji/svg) in `build/ios/Twemoji.xcassets` as an image set that keeps its vectors, named as its file is (`1f62d`), and the project takes it from there with [`design/twemoji/sequences.txt`](../design/twemoji/sequences.txt), which says which emoji each picture is. Settings credits Twemoji, under its CC-BY 4.0 licence.

The core builds for iOS with Calx's iOS targets ([CLX-408](https://acta.aaenz.no/aaen-studios/clx#CLX-408), [CLX-410](https://acta.aaenz.no/aaen-studios/clx#CLX-410)): nightly 202611231257 or newer, so the Calx loom is pinned to in [`.calx-version`](../.calx-version).

A build without the core (`--sample`, or `xcodegen` run by hand) runs on [`SampleCore`](Loom/Core/SampleCore.swift): sample agents and chats, a reply that streams, and a question to answer, in the frames the core sends. SwiftUI previews use it too. With the core linked, `-sample` at launch runs on it as well.

To run against an instance, set `LOOM_SERVER` in the scheme's environment, or type its address on the sign-in screen.

## Testing it against an instance

```sh
calx scripts/ios.calx --sim
calx tests/ios/live.calx
```

[`tests/ios/live.calx`](../tests/ios/live.calx) starts an instance with the fake agent ([tests/README.md](../tests/README.md)), builds the app, and runs it in the simulator, headless: it joins with the QR code's text, a reply streams in, it answers a question, and it follows the instance when it moves. Each step is checked on the instance, and each screen is a screenshot in `build/ios/live/`. With no one to tap, a debug build takes these from its launch arguments, each doing what its screen's button does: `-link <qr>` joins, `-say <text>` sends to the agent `-open` opened, `-allow` answers its questions yes, `-signIn` taps Sign in on its sign-in cards, and `-callback <url>` hands the app what a browser brought back to the `loom:` redirect (`fromLaunch` in [`Session.swift`](Loom/App/Session.swift)).

## Files

- [`Loom/Core/`](Loom/Core/): the C boundary. [`Core.swift`](Loom/Core/Core.swift) starts the core with its config (its cache in Application Support/Loom), sends it frames, and hands what it says to the main actor in batches. [`JSON.swift`](Loom/Core/JSON.swift) is the frames' JSON. [`SampleCore.swift`](Loom/Core/SampleCore.swift) stands in for the core without it.
- [`Loom/Model/Model.swift`](Loom/Model/Model.swift): what the screens show, as the core tells it, as [`desktop/src/model.rs`](../desktop/src/model.rs) does for the desktop app. Lists come from the core's cache with `core.get` and are fetched again when an event says they changed. Only a reply still being written lives here alone, from its deltas.
- [`Loom/Model/Rooms.swift`](Loom/Model/Rooms.swift): the group chats (PLAN.md, "Group chats"), as [`desktop/src/model/rooms.rs`](../desktop/src/model/rooms.rs) has them: each conversation's `room`, the one open in the chat's place, how each reply came to its agent (`routed`), and the commands the person's changes send. New group chat's form is the model's too, as the desktop's `room_panel` has it (`newRoom`): the members and colour picked (`roomForm`), started empty when the sheet opens, Make on once it has a name and two members (`Room.minMembers`, which a group chat's settings keep too), and the `room.create` it sent, during which Make does nothing, so a quick second tap makes no second one, until it's answered, 15 seconds pass (`makeWait`, timed by `Session.makeRoom`) or the connection goes. [`RoomViews.swift`](Loom/Views/RoomViews.swift) draws them: their rows atop the agent list under Group chats, each with its members' threads woven together, the line over each reply, "→ Ledger · money question", in the agent's colour, whose menu sends the person's message to another member, and the sheets that make a group chat or change one, its corrections each swiped away to forget it.
- [`Loom/App/`](Loom/App/): the app, and [`Session.swift`](Loom/App/Session.swift), which joins the core, the model and the system: `app.active` and `app.wake` as the app comes and goes, `app.network` when the network changes, `core.device_ask` for the clipboard, and `core.notify` as a notification. [`Notifications.swift`](Loom/App/Notifications.swift) asks for permission, and gives an approval Allow and Deny.
- [`Loom/Views/`](Loom/Views/): the screens. [`Cards.swift`](Loom/Views/Cards.swift) has the cards in a chat in the desktop's one frame: the service's badge or an icon at its start (`BadgeView`, from `shared/badge.calx`), the title with the agent's thread beside it, tugging while the card waits for the person, where it goes under it, and what it does in a pill; an agent's `show_card`, with choices as tiles, two to a row, which answer once the reply is finished, and a form (`FormCard`) of boxes, choices and switches sent with one **Send**; a risky question's **Allow** held until it fills (`HoldButton`); loom's "Sign in to acta" for an MCP server, which opens its sign-in page over the app ([`SignIn.swift`](Loom/App/SignIn.swift)) and catches the browser coming back to `loom:/callback` (`mcp.sign_in`, `mcp.signed_in`), then says whom the person is signed in as once `mcp.list` says so, or why a sign-in didn't finish; an MCP server an agent proposed, with loom's knot (`Knot`) and the server's badge joined by the agent's thread (`SpanView`), slack while it waits and pulled straight once it's connected, its address or command, its settings, a masked field for each secret the person doesn't have, **Add** and **Cancel**, then **Sign in** and **Later** for one that needs it (`mcp.add_answer`), its tools once it's connected, and one quiet line once it's settled otherwise; what an agent's page wants that only the person knows (`browser_ask_secret`), with the site's badge, or a key for a file, the site under the title, a field for each thing asked, masked as the card says with an eye to show it, under its label, **Save as** with the name it's offered to be kept as, **Fill** and **Not now** (`browser.secret`), and one quiet line once it's answered; and the questions an agent waits on, as the core put them in words: steps, the agent's reason, **Allow** with **Always allow** in the menu beside it, **Deny** and **Details**.
- [`Loom/Design/`](Loom/Design/): loom's colours and type from the design tokens ([`design/generated/Tokens.swift`](../design/generated/Tokens.swift), with the `phone` sizes), each agent's thread, and Markdown. [`Emoji.swift`](Loom/Design/Emoji.swift) finds emoji and the person's own (`<:name:id>`) in a message's words and draws them with Twemoji at the words' size, or about 48 points in a message of only one to three; [`Model/Emojis.swift`](Loom/Model/Emojis.swift) keeps what the core says of them, and [`Views/EmojiViews.swift`](Loom/Views/EmojiViews.swift) has the suggestion row, the picker and Settings → Emoji.

## The screens

- **Sign in**: **Scan a code**, VisionKit's scanner reading the QR code another device shows under Add a device, or the code pasted, `K7QF-M2XD@loom.example.com` (`link`, with the text). Then the check, four digits, until the person says yes on the other device, with Cancel. **Sign in with a password** has the instance's address, a username and a password (`login`). The simulator has no camera, so there the QR code's text can be pasted. A `loom://add?…` link opens the app at the check.
- **Agents**: each agent as one ongoing chat, with its thread and what it's doing, as the desktop's sidebar shows them, or while it rests, its program by the name people know (`acp.list`'s `title`, such as "Claude Agent"). They're grouped as the desktop's sidebar groups them ([PLAN.md, "The sidebar"](../PLAN.md#the-sidebar)): Waiting on you, the rest, each folder under its name, which a tap opens and shuts and a long press renames or deletes, and Hidden, shut until opened. A long press on an agent has Move to folder (each folder, Remove from folder, and New folder, named in an alert) and Hide or Show.
- **A chat**: as the desktop draws it ([PLAN.md, "One answer at the end"](../PLAN.md#one-answer-at-the-end)). The person's bubbles are a breath of the agent's colour, the default, or with Vibrant bubbles the colour itself. What another agent sent (`message_agent`) sits on the person's side too, its bubble a breath of the sender's colour, with the sender's thread and name in its colour over it. The chat is always the person's own with the agent: another agent's thread with it, however new, is in the chat's menu as "From Casper", which opens it to read, titled by Casper's thread, with **Continue in your own chat** in the composer's place, which goes back to the agent's chat with the cursor in its composer. A reply's answer sits in a grey bubble, or is plain text if the person picked that, with Markdown and code blocks, one answer at the end, its steps (thoughts, tool calls in their places, and what it said on the way, smaller and quieter) folded under one line that shows the step it's on while it works. A routine's quiet run isn't drawn, and its old prompts aren't shown; what it posts is. Pictures are sized from their file's header before they load, to fit the column and 360 × 400. Two or more together are one fan of 240 × 180, as the desktop draws it at rest ([PLAN.md, "Files and images"](../PLAN.md#files-and-images)): the first in front, and up to four more tilted behind it, a little quieter, each with the bubble's corners, a fine edge and a soft shadow. Two put the second behind on the right; three, one each side; four, three tight behind, the extra one on the left; five or more, two tight each side, and only five are drawn. The model lays them out (`fanCards`) and says what the front card's corner shows (`fanCount`): how many there are, all of them. The fan keeps the room its tilted cards reach into, on the message's side. A tap opens them big over everything, at the first, a page each to swipe through, with each one's name and "1 / 3", which stay put. Each is laid out at its final shape from the first frame, as the instance gave its width and height, or its thumbnail's shape, its thumbnail scaled up there until it's whole, then faded over (`WholePicture`). A pinch zooms it toward the fingers, a drag pans it with the scroll view's give at its edges, and a double tap goes between its fit and zoomed in (`ZoomingPicture`); zoomed in, it's decoded whole, and a swipe pans it rather than going to the next. In any message's words an agent it mentions shows as its thread and its name in its colour, a little weathered, and a file it mentions, or one sent with it, as its icon (a tiny copy of a picture sent with it) and its name, underlined, which opens it (`agent.file`, or the file itself). A picture a reply names from its agent's folder or the shared one shows in the reply from its thumbnail (the mention's `thumb`), alone or two or more in a fan, with a tiny copy of it before its name in the words, and a tap has the instance keep it (`agent.file`) and opens it big, as a picture a reply names opens wherever it's tapped (`viewNamed`). Then questions with Allow and Deny, and the composer, with photos (sent as JPEG) and files. Typing `@` at the start or after a space opens a picker over it: the person's other agents whose names match, with the first line of their instructions, then the files that match in the agent's folder and the shared one (`agent.files`), with their folder. A tap puts `@Casper` or the file's name in the field, which goes as its link (`[@Casper](loom:agent/a_2)`, `[hours.md](loom:file/a_1/notes/hours.md)`) if it's still there when the message is sent. A swipe right on a message, or Reply in its long-press menu, starts a reply to it, and Select text there quotes a part with Quote, or in an agent's reply Ask about this: the composer shows whom it replies to over its words with its ×, and the sent message has the quote over its bubble, which goes to the original and lights it (`QuoteView`, `Model.loadFurtherBack`). Emoji show as Twemoji draws them, big in a message of only one to three, and the person's own as their pictures. In the composer, an emoji from the keyboard becomes a piece drawn the same way; `:` and two letters bring a row of up to eight over it, the person's own first, and `:sob:` closed with its colon becomes the emoji. The smiley before Send, or Emoji in the + sheet, opens the picker: **Find an emoji**, the skin tone, a tab for each group, and the grid, with a dashed + under Your emoji that opens Settings → Emoji. Copy gives the person's own as `:name:`.
- **Settings**: the account, the instance, **Add a device** (the QR code and the code, Copy code and Share link), the person's devices with when each was last connected, a swipe removing one, **Set a password** when the account has none, **Secrets** (each secret by name with the sites it may be filled in on, a swipe taking a site off or removing it, and a form for one more), the chat (Agent replies, Bubbles or Plain, and Vibrant bubbles, kept on the phone), **Emoji** (the person's own as tiles, with Add from Photos, which names it, and Rename and Delete in each one's menu with Undo; the skin tone; Turn :) into 🙂; and the smiley in the composer, whose own menu hides it too), the credits, notifications, and signing out.

When the instance moves, the core follows it and the app says so: "Your instance moved to …". A move the core won't follow (`moved_unsigned`, `moved_elsewhere`) shows the core's reason, and the app stays where it was.

For a screenshot of each screen, launch it with `-sample`, and `-signedOut`, `-open <agent id>` (with `-thread <conversation>` for another agent's thread with it, such as `-open a_4 -thread c_5`, and `-continue` to tap its Continue in your own chat, or `-reply <message>` for a reply to that message in the composer, such as `-open a_1 -reply msg_2`, or `-pins` for the chat's pins, such as `-open a_4 -pins`), `-settings` or `-settings -addDevice`: `xcrun simctl launch booted no.aaenz.loom -sample -open a_1`. With `-open`, `-plus` opens the composer's + sheet, and `-plus skills`, `-plus routines` or `-plus recent` that list in it. A debug build also takes what the composer and the chat would get from a tap, each as its button or a paste does: `-skill <name>` picks that skill, `-recent <name>` that recent file, `-attach <path>` attaches a file, `-paste <url>` pastes a link, each again for more, and `-view` opens the chat's last pictures in the viewer, `-type <text>` types it in the composer as the keyboard would (`-type ":ta"` for the emoji row), and `-emoji` opens the emoji picker; with `-settings`, `-emojiSettings` opens Settings → Emoji: `xcrun simctl launch booted no.aaenz.loom -sample -open a_4 -skill review -paste https://example.com`.

## Push

Notifications show while the app runs, from the core's `core.notify`. Push to the lock screen goes through APNs, from the instance or through the push relay ([protocol.md, "Push"](../protocol/protocol.md#push)):

- **Permission**: Settings → Notifications asks, and on a yes the app registers with APNs.
- **The token**: `Session.registered(pushToken:)` keeps it, and sends the core `push.register` with `token` and `env` on each `welcome`, since the core sends a command only while it's connected. The core seals it for the push relay when `welcome` has a `relay`.
- **Allow and Deny**: an `approval.needed` notification has both, answered as `approve` without opening the app.
- **Still to come** ([LOO-253](https://acta.aaenz.no/aaen-studios/loom#LOO-253)): the `aps-environment` entitlement and signing with Elliot's Apple team, the notification service extension that opens the push relay's sealed notifications with `loom_push_open`, and TestFlight. Until then the app gets no APNs token, so notifications show only while it runs.
