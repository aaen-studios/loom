# server

Calx: the instance, and the `loom` program.

- [`main.calx`](main.calx): the `loom` command line: `serve`, `user add`, `user list`, `acp add`, `acp list`, `files limit`, `push key` (the APNs key, kept sealed) and `push off`, `status` (which also says the user it runs as and whether push is on), `update`, `mcp` and `version`. `serve` won't run as root or an elevated Administrator unless given `--allow-root`, and the tests pass it, since GitHub's Windows runners are elevated. Every command but `serve` and `mcp` takes `--json`, and answers with one JSON object, or `{"error":{"code","message"}}` and a non-zero exit, so an agent over SSH reads it reliably. `install` sets loom up on a server (below). Later `loom receive`.
- [`mcp.calx`](mcp.calx): `loom mcp`, loom's own tools as an MCP server on standard input and output. The instance gives it to every agent's session, and it hands each call back to the instance. The tools are in [`shared/tools.calx`](../shared/tools.calx).
- [`instance.calx`](instance.calx): one loop on std.http.server, listening on 127.0.0.1. It serves the HTTP routes and the `/ws` WebSocket from [protocol.md](../protocol/protocol.md), and runs each agent's turns through ACP, turning what the agents say into events and deltas.
- [`store.calx`](store.calx): SQLite. Every row is kept per person, and that includes the event log. What only the instance should read (secrets, ACP programs' settings, webhook secrets) is sealed under `secret.key`, beside the database.
- [`hashing.calx`](hashing.calx): argon2id hashing on a thread of its own, so a login doesn't hold up the loop.
- [`acp.calx`](acp.calx): the ACP client. Each agent program runs as a process of its own, written to and read by a thread of its own.
- [`backup.calx`](backup.calx): `loom export` and `loom import` (PLAN.md, "Moving an instance"). An instance's data folder goes into one `.tar.zst`, a file at a time: the database as a consistent snapshot (`VACUUM INTO`, safe while it runs), `secret.key`, and the folders, but not `acp/` (ACP programs for one machine) or `plugins/` (written again). Import makes a new instance in an empty folder and says which ACP agents to install again. `loom serve --backups DIR` writes one there each day, on a thread of its own, and keeps the newest 7 (`--backups-keep`).
- [`move.calx`](move.calx): moving an instance (PLAN.md, "Moving an instance"). `loom receive` prints a one-time move code and takes the move; `instance.move` sends the export there in chunks on a thread of its own. Each chunk is sealed with XChaCha20-Poly1305 under a key from the code, which also gives the bearer token, and the last request says how many there were, so none can be left out or reordered.
- [`noise.calx`](noise.calx): the network side of an instance in the desktop app, once the owner turns phones on (`instance.phones`). A bridge on a thread of its own listens on every address, on port 47420 if it can, and takes only `/ws/noise`: the Noise NK handshake against the instance's X25519 key, then each phone's frames to its own `/ws` on loopback and its HTTP requests to the instance's routes, both ways sealed. Anything else there gets `noise_only`.
- [`installer.calx`](installer.calx): ACP agents from the ACP Registry, on a thread of its own: reading the registry, and downloading, checking and unpacking an agent. `serve --registry` points it at a mirror.
- [`plugins.calx`](plugins.calx): plugins (PLAN.md, "Plugins"): reading a plugin's `plugin.toml` and checking its files, what it asks for (`tools`, `agents`, `cmd:<name>`), and what of that waits for its person's yes. The instance keeps plugins with a revision for each change, a panel's data (1 MB at most), and runs an allowed plugin's tool server for every agent, from a folder of its files.
- [`routines.calx`](routines.calx): when a routine runs next, from its schedule: every N minutes, or daily or on weekdays at a time of day in its time zone, through std.time's `TimeZone`. The instance looks for routines that are due once a second, and runs them as a prompt to their agent (PLAN.md, "Routines"). `POST /hooks/<id>` runs one from outside, with its secret. `serve --test-minute-ms` shortens the minute, for tests.
- [`setup.calx`](setup.calx): `loom install`, run as root on a Linux server: the `loom` user (no shell, no rights beyond `/var/lib/loom`, which only it can read), the program in `/usr/local/bin`, a hardened systemd unit that runs `loom serve` as `loom`, and Caddy for TLS with `--domain`, or `tailscale serve` without one. It starts the service and gives the address and the setup code from its log. A second run brings it up to date, and it leaves alone a unit or a Caddyfile it didn't write.
- [`install.sh`](install.sh): what a fresh server runs, `curl -fsSL https://github.com/aaen-studios/loom/releases/latest/download/install.sh | sudo sh` (`-s -- --domain loom.example.com` for a domain). It only fetches the release's `loom` for the machine, checks its SHA-256 against the manifest, and runs `loom install`. CI runs it on a fresh Ubuntu runner.
- [`push.calx`](push.calx): push to the iPhone app through APNs, on a thread of its own: a provider token signed ES256 with the owner's APNs key, made again every 50 minutes, and an HTTP/2 POST per phone. The instance hands it a notify, a question, or a reply the person isn't there to see, for each phone that isn't connected, and forgets the tokens APNs says are gone (protocol.md, "Push"). `serve --test-apns` points it at a fake APNs, for tests.

Trying it from source, from the repository's root:

```sh
calx server/main.calx acp add claude npx -y @agentclientprotocol/claude-agent-acp
calx server/main.calx serve                       # prints a setup code on the first start
```

Then `POST /api/setup` with the code makes the owner. `echo "a password" | calx server/main.calx user add bob` adds a second account. Everything is kept in `loom-data/` unless `--data` names another folder. [`tests/protocol/phase1.calx`](../tests/protocol/phase1.calx) shows a whole session.

The same code is compiled into the desktop app's library for an instance with no server ([PLAN.md](../PLAN.md#an-instance-in-the-desktop-app)).
