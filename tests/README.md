# tests

- **The fake ACP agent** ([`fake_agent/main.calx`](fake_agent/main.calx)): a Calx program that speaks ACP over stdio, as `claude-agent-acp` does, and plays the turn its prompt spells out, one step a line: text to say, `/think`, `/plan`, `/tool`, `/ask` (a tool call that asks permission), `/slow` and `/sleep`, `/stop` with a stop reason, `/fail` and `/crash`, `/files` (says what files came with the prompt) and `/image` (sends a small PNG back). So sessions, approvals, cancelling and crashes are tested without a real model. The comment at its top lists every step. Run it with `calx tests/fake_agent/main.calx`.
- **Protocol tests** ([`protocol/`](protocol/)): Calx scripts that drive a real instance through HTTP and the WebSocket, as an app would. [`phase1.calx`](protocol/phase1.calx) sets up the owner, adds a second account, chats with the fake agent, drops the connection in the middle of a reply and catches up, answers an approval, cancels a run, and checks the second account sees none of it. With `LOOM_TEST_CLAUDE="npx -y @zed-industries/claude-agent-acp"` set, it also chats with Claude.
  [`files.calx`](protocol/files.calx) sends files up and back, checks only their owner can read them and that images get thumbnails, sends them to the agent and takes an image back, searches, and holds the storage limit. [`core_conn.calx`](protocol/core_conn.calx) and [`local.calx`](protocol/local.calx) test the core's connection and the instance in the desktop app. [`../kit.calx`](kit.calx) has what they share: starting an instance with the fake agent, HTTP calls, and an app's session.
- **End-to-end tests:** the real apps against an instance with the fake agent.

Unit tests live beside the code, as `@test` functions run with `calx test`. `calx scripts/check.calx` runs them all.
