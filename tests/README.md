# tests

- **The fake ACP agent** ([`fake_agent/main.calx`](fake_agent/main.calx)): a Calx program that speaks ACP over stdio, as `claude-agent-acp` does, and plays the turn its prompt spells out, one step a line: text to say, `/think`, `/plan`, `/tool`, `/ask` (a tool call that asks permission), `/slow` and `/sleep`, `/stop` with a stop reason, `/fail` and `/crash`, `/files` (says what files came with the prompt) and `/image` (sends a small PNG back). So sessions, approvals, cancelling and crashes are tested without a real model. The comment at its top lists every step. Run it with `calx tests/fake_agent/main.calx`.
- **Protocol tests** ([`protocol/`](protocol/)): Calx scripts that drive a real instance through HTTP and the WebSocket, as an app would. [`phase1.calx`](protocol/phase1.calx) sets up the owner, adds a second account, chats with the fake agent, drops the connection in the middle of a reply and catches up, answers an approval, cancels a run, and checks the second account sees none of it. With `LOOM_TEST_CLAUDE="npx -y @agentclientprotocol/claude-agent-acp"` set, it also chats with Claude.
  [`files.calx`](protocol/files.calx) sends files up and back, checks only their owner can read them and that images get thumbnails, sends them to the agent and takes an image back, searches, and holds the storage limit. [`core_conn.calx`](protocol/core_conn.calx) and [`local.calx`](protocol/local.calx) test the core's connection and the instance in the desktop app; the first also has a second core join by the QR code the first shows, once. [`core_noise.calx`](protocol/core_noise.calx) has a real core join an instance in the desktop app over Noise from a QR code with a `noise://` place, past an address that answers nothing, then connect and send and fetch a file; a place with another key is unreachable. [`core_move.calx`](protocol/core_move.calx) has a core follow its instance to a new place, once the new place answers with the same key. [`tools.calx`](protocol/tools.calx) has the fake agent call loom's own tools through `loom mcp`: one agent hands work to another, edits its instructions, makes agents and sends a notification, and deleting or changing a permission mode waits for the person's yes. Agents remember notes, recall them by their words, and read the shared ones of other agents. [`registry.calx`](protocol/registry.calx) serves an ACP Registry from a folder, with the fake agent built and zipped as a binary release, installs it with a setting, runs an agent on it, and checks a wrong SHA-256, an agent with no build here, and a member are refused. [`sessions.calx`](protocol/sessions.calx) restarts the instance and checks each conversation picks its ACP session up again, with `session/load` or `session/resume`, or starts a new one. [`events.calx`](protocol/events.calx) prunes events and checks a device from before what's left, or a new one, gets a snapshot. [`servers.calx`](protocol/servers.calx) sets up MCP servers and a secret, and checks an agent's session gets the ones it has, with the secret filled in, and the database keeps it only sealed. [`devices.calx`](protocol/devices.calx) runs a real core as a PC that offers tools, and checks an agent reads a file there, is refused a tool that's off, and runs a command only once the PC itself says yes. [`routines.calx`](protocol/routines.calx) runs routines with a minute that lasts 100 ms, and checks they post into their agent's chat on schedule and notify, that daily and weekday ones run next at their time in their time zone, pause, run by hand, are made and deleted by agents with the person's yes, and catch up after a restart or not, as each says. [`webhooks.calx`](protocol/webhooks.calx) runs a routine from its webhook, signed as GitHub signs and with a bearer secret, checks its agent gets what was posted, and that a wrong secret, a forged signature, a paused routine and an unknown hook are turned away. [`plugins.calx`](protocol/plugins.calx) puts plugins from the person and from an agent, checks what an agent's asks waits for the person's yes and that an allowed tool server is in new sessions, keeps a panel's data up to its limit, and deletes one from an agent once the person says yes. [`backup.calx`](protocol/backup.calx) exports a running instance, imports it into a new folder and starts there, and checks the same token sees its agents, conversations, files and secrets. [`move.calx`](protocol/move.calx) moves an instance to a `loom receive` with an app connected: only the owner can, an agent asks first, and a wrong code moves nothing. The app gets a moved frame signed with the key `welcome` gave it, the old place keeps saying where it went, and the new place takes the same token from the same event number, with the same key and everything there. [`noise.calx`](protocol/noise.calx) turns phones on and checks the network port takes only `/ws/noise`, that a handshake against another key goes nowhere, and that a phone with the key from `link.create` joins, says hello, and sends and fetches a file bigger than one Noise message through the one socket. Phones stay on across a restart, on the same port with the same key, and turning them off closes the socket. [`sandbox.calx`](protocol/sandbox.calx), with Podman and pasta on Linux, builds an image with `loom` and the fake agent and runs a member's agent in her sandbox: it gets her own secrets but not the owner's program settings, has its home in her folder whatever folder it names, reaches loom's tools through the gate, and a file it links to is read in the sandbox, so the instance's database isn't. Removing her removes the sandbox and the folder. Elsewhere it says it was skipped. [`people.calx`](protocol/people.calx) has the owner invite someone, who joins once with a one-use invite, while a wrong code, a taken username and a weak password are refused. A member can't invite or list people, an admin invites members but not admins, a person deletes their own account but the owner can't, someone removed loses their session and token, and a member's agent doesn't run on an instance without sandboxes. Real cores give the invite and reset links, a new core joins from one, and a reset link sets a new password once; `loom user password` resets the owner's and signs their devices out. [`push.calx`](protocol/push.calx) registers a phone's APNs token, refuses one that isn't, and sets up the APNs key from the command line, kept only sealed. Then, against a fake APNs, it checks a reply comes to the phone when the person is on none of their devices, a question with Allow and Deny and a notify come to a phone that isn't connected, each with a provider token signed with the key, a connected phone gets none, and a token APNs calls gone gets no more. [`update.calx`](protocol/update.calx) serves releases from a folder and checks the updater takes a signed one and refuses one signed with another key, or with a file that isn't the one named. [`../kit.calx`](kit.calx) has what they share: starting an instance with the fake agent, HTTP calls, and an app's session.
- **End-to-end tests:** the real apps against an instance with the fake agent.

Unit tests live beside the code, as `@test` functions run with `calx test`. `calx scripts/check.calx` runs them all.
