# tests

- **The fake ACP agent** ([`fake_agent/main.calx`](fake_agent/main.calx)): a Calx program that speaks ACP over stdio, as `claude-agent-acp` does, and plays the turn its prompt spells out, one step a line: text to say, `/think`, `/plan`, `/tool`, `/toolout` (a tool call that completes with the output it's given, as a T3 tool's), `/ask` (a tool call that asks permission), `/slow` and `/sleep`, `/nap MS` (waits while it goes on answering other sessions, as a real agent's sessions run side by side), `/stop` with a stop reason, `/fail` and `/crash`, `/files` (says what files came with the prompt), `/image` (sends a small PNG back), `/write` and `/picture` (write a file or a PNG, as an agent makes one), `/net HOST:PORT` (whether it reaches there straight, and through the proxy `HTTPS_PROXY` names) `/act` (a tool call with its own rawInput that asks permission, for rules on what it touches), `/shell` (a shell command as Claude's adapter plays one, titled with the whole command), `/selfprompt` (a `user_message_chunk`, as a prompt the program gives itself), `/subagent` (a Task call whose calls and words are tagged with its id, as Claude's adapter tags a subagent's), `/named` (a call titled by the update that finishes it), `/askonly` (a permission request for a call it never sent a `tool_call` for), `/open` (a call it never reports on again) `/askopen` (a permission request for a call it never reports on, whatever the answer), `/compacted` (a `usage_update` after its turn has ended, as Claude's adapter reports a session it compacted while idle), `/next` (a step it plays at the start of its next turn, as when loom gives it a turn of its own), `/mcpkeep` (a call to `loom mcp` through one the session keeps, as a real agent keeps its servers), `/mcpnew` (a call to `loom mcp` as a client of MCP 2026-07-28, with no initialize) and `/uptime` (how long ago it started). So sessions, approvals, cancelling and crashes are tested without a real model. The comment at its top lists every step. Added again with `--limited` it answers every prompt with a usage-limit error, and with `--broken` it doesn't initialize, so a backup program's taking over is tested too. With `--record=PATH` it writes a JSON line to PATH for each prompt, before it answers it (its session, its turn there, the characters it was sent and the session had before it, the `[loom: …]` notes in it, how much it answered, whether it was asked for a summary, its model and effort, and the start of its text and what came with it), and one for each `session/close`, so a test sees what a turn costs; it offers `session/close` always. With `--log=PATH` it writes "started" to PATH when its program starts and "picked up SESSION" for each session it loads or resumes, so a test can wait for a program loom starts without sending it anything (`prestart.calx` does). Run it with `calx tests/fake_agent/main.calx`.
- **The fake container runtime** ([`fake_runtime/main.calx`](fake_runtime/main.calx)): takes `exec -i BOX loom ARGS` as Podman or Docker would, and runs the `loom` built beside it with ARGS, so a sandbox's egress is tested on any computer.
- **The fake MCP server** ([`fake_mcp/main.calx`](fake_mcp/main.calx)): MCP over stdio, with three tools: `echo` (only reads, and gives structured content), `add` (changes something, so it asks) and `key_length` (how long its `FAKE_KEY` is, so a test sees a secret reached the server). Code Mode's test gives it to an agent as the person's MCP server. `FAKE_ERA` makes it a server of one era of MCP or the other, or both, in the ways a real one can be (`legacy`, `old`, `odd`, `silent`, `exits`, `modern`, `dual`, `newer`, `slow`), with tools that say the version they were called in and the `Mcp-Param` header they were given, and one whose `x-mcp-header` breaks MCP's rules; with `--http` it's a server over Streamable HTTP that checks a request's headers match its body. With `FAKE_GROW` its tools change: `grow` adds `grown`, and it says so with `notifications/tools/list_changed`, in the legacy era at once and in the modern era on the `subscriptions/listen` stream that asked for it, which over HTTP is an event stream that stays open; there `/test/grow?name=NAME` adds a tool, `/test/drop` ends every stream, and `/test/stats` says how many streams it was asked for, how many are open and the sign-in the last came with.
- **The fake OAuth MCP server** ([`fake_oauth/main.calx`](fake_oauth/main.calx)): MCP over HTTP that answers 401 without a live token, with the authorization servers it signs in at: `/mcp`, whose 401 names its metadata and whose authorization server lets apps sign up; `/mcp2`, whose metadata is at its well-known place and whose authorization server takes only one client, with its secret sent as HTTP Basic; `/api/mcp`, which signs no one in and takes only the key `Bearer fake-key`, as a server with a token the person made does; and `/mcp3`, whose authorization server takes Client ID Metadata Documents (loom's, read from `site/public/client.json`, for the return addresses it names) and lets apps sign up too. It checks the client and redirect, the PKCE challenge against the code's verifier, the resource and a code used once, renews tokens with refresh tokens used once, and revokes. A token has the scopes its sign-in asked for, and `whoami` with `as: "admin"` needs `admin`, answering 403 `insufficient_scope` without it. `/test/stats` (with what the last app that signed up asked for, and how many sign-ins were by the document's client), `/test/expire` and `/test/life?s=N` let a test see and steer it.
- **The fake Acta** ([`fake_acta/main.calx`](fake_acta/main.calx)): Acta's MCP server over HTTP at `/api/mcp`, taking only the key `Bearer acta-key`, with `list_boards` (loom, `LOO`, and calcite, `CAL`) and `get_task` for four cards, `LOO-206` in progress with its assignee, size, labels, description, subtasks and four comments, `LOO-207` to do, `LOO-351` done and `CAL-338` in review, and an error for any other; `get_board` with each board's labels and people; `list_tasks` by status (the open ones when none is asked), words and label; `update_task` for a status and subtasks ticked or not; `create_tasks`, whose cards are numbered from 400 with the board's prefix (`LOO-400`), with an error for a label that isn't the board's; and `list_activity`, a board's changes since a time, newest first, in Acta's words. Beside it a fake T3 at `/t3/mcp`, taking only `Bearer t3-key`, with `t3_thread_launch`, `t3_thread_wait`, which answers at once, timed out while a run goes on, and `t3_thread_read`. `/test/calls` says how often each was called, `/test/status?task=&status=&by=` moves a card, which its activity says, `/test/activity?task=&text=&by=` adds other activity, and `/test/t3/start?thread=&title=` and `/test/t3/finish?thread=&status=&text=` start and end a thread's run. The instance takes it for Acta with `serve --test-acta URL`.
- **The fake T3** ([`fake_t3/main.calx`](fake_t3/main.calx)): T3 Code's MCP server over HTTP at `/mcp`, taking only `Bearer t3-key`, with `t3_project_list` (loom, `p1`, and calcite, `p2`), `t3_thread_read`, `t3_pending_request` (list, read and respond to a question; approvals aren't listed, as in T3), `t3_thread_launch` and `t3_thread_send`, and T3's WebSocket API at `/ws` with a ticket from `POST /api/auth/websocket-ticket`, which answers `runtime-request.respond`. Unit tests live beside the code, as `@test` functions run with `calx test`. `calx scripts/check.calx` runs them all. The desktop app's are Rust tests run with `cargo test` in `desktop/`, and the iPhone app's are in [`ios/LoomTests/`](../ios/LoomTests/), run on a Mac with `xcodebuild test` ([ios/README.md](../ios/README.md#testing-it)).
