# tests

- **The fake ACP agent** ([`fake_agent/main.calx`](fake_agent/main.calx)): a Calx program that speaks ACP over stdio, as `claude-agent-acp` does, and plays the turn its prompt spells out, one step a line: text to say, `/think`, `/plan`, `/tool`, `/ask` (a tool call that asks permission), `/slow` and `/sleep`, `/stop` with a stop reason, `/fail` and `/crash`, `/files` (says what files came with the prompt), `/image` (sends a small PNG back), `/net HOST:PORT` (whether it reaches there straight, and through the proxy `HTTPS_PROXY` names) and `/act` (a tool call with its own rawInput that asks permission, for rules on what it touches). So sessions, approvals, cancelling and crashes are tested without a real model. The comment at its top lists every step. Added again with `--limited` it answers every prompt with a usage-limit error, and with `--broken` it doesn't initialize, so a backup program's taking over is tested too. Run it with `calx tests/fake_agent/main.calx`.
- **The fake container runtime** ([`fake_runtime/main.calx`](fake_runtime/main.calx)): takes `exec -i BOX loom ARGS` as Podman or Docker would, and runs the `loom` built beside it with ARGS, so a sandbox's egress is tested on any computer.
- **The fake MCP server** ([`fake_mcp/main.calx`](fake_mcp/main.calx)): MCP over stdio, with three tools: `echo` (only reads, and gives structured content), `add` (changes something, so it asks) and `key_length` (how long its `FAKE_KEY` is, so a test sees a secret reached the server). Code Mode's test gives it to an agent as the person's MCP server.
- **Protocol tests** ([`protocol/`](protocol/)): Calx scripts that drive a real instance through HTTP and the WebSocket, as an app would. [`phase1.calx`](protocol/phase1.calx) sets up the owner, adds a second account, chats with the fake agent, drops the connection in the middle of a reply and catches up, answers an approval, cancels a run, and checks the second account sees none of it. With `LOOM_TEST_CLAUDE="npx -y @agentclientprotocol/claude-agent-acp"` set, it also chats with Claude.
  [`files.calx`](protocol/files.calx) sends files up and back, checks only their owner can read them and that images get thumbnails, sends them to the agent and takes an image back, searches, and holds the storage limit. [`core_conn.calx`](protocol/core_conn.calx) and [`local.calx`](protocol/local.calx) test the core's connection and the instance in the desktop app, whose QR code, with phones on, names the computer over Noise at its addresses on the network; the first also has a second core join by the QR code the first shows, once. [`core_noise.calx`](protocol/core_noise.calx) has a real core join an instance in the desktop app over Noise from a QR code with a `noise://` place, past an address that answers nothing, then connect and send and fetch a file; a place with another key is unreachable. The instance says where it is with mDNS, under its Noise key, and a relay whose only address answers nothing finds it that way and gets through. [`core_move.calx`](protocol/core_move.calx) has a core follow its instance to a new place, once the new place answers with the same key. [`tools.calx`](protocol/tools.calx) has the fake agent call loom's own tools through `loom mcp`: one agent hands work to another, edits its instructions, makes agents and sends a notification, and deleting or changing a permission mode waits for the person's yes, while a looser one than the agent's own is refused. Agents remember notes, recall them by their words, and read the shared ones of other agents. [`registry.calx`](protocol/registry.calx) serves an ACP Registry from a folder, with the fake agent built and zipped as a binary release, checks each agent comes with its icon the instance fetched, that it keeps what it read for a restart, and which registry agent each program is, installs it with a setting, runs an agent on it, and checks a wrong SHA-256, an agent with no build here, and a member are refused. Then `loom acp install` installs it straight into another data folder with `--env` settings, `loom acp settings` sets and removes them, both giving only their names and keeping them sealed, and an agent with no build here says why. [`sessions.calx`](protocol/sessions.calx) restarts the instance and checks each conversation picks its ACP session up again, with `session/load` or `session/resume`, or starts a new one. [`endless.calx`](protocol/endless.calx) has the fake agent report its context with `usage_update`, and checks a session with room keeps going, while after one nearly fills the next message goes to a fresh session that's given the newest of the chat, without its own message twice, and told `search_messages` has the rest, and the message after stays there. [`events.calx`](protocol/events.calx) prunes events and checks a device from before what's left, or a new one, gets a snapshot. [`servers.calx`](protocol/servers.calx) sets up MCP servers and a secret, and checks an agent's session gets the ones it has, with the secret filled in, and the database keeps it only sealed. [`devices.calx`](protocol/devices.calx) runs a real core as a PC that offers tools, and checks an agent reads a file there, is refused a tool that's off, and runs a command only once the PC itself says yes. [`routines.calx`](protocol/routines.calx) runs routines with a minute that lasts 100 ms, and checks they post into their agent's chat on schedule and notify, that daily and weekday ones run next at their time in their time zone, pause, run by hand, are made and deleted by agents with the person's yes, and catch up after a restart or not, as each says. [`webhooks.calx`](protocol/webhooks.calx) runs a routine from its webhook, signed as GitHub signs and with a bearer secret, checks its agent gets what was posted, and that a wrong secret, a forged signature, a paused routine and an unknown hook are turned away. [`quiet.calx`](protocol/quiet.calx) has routine runs call `routine_quiet`, which leaves nothing in the chat (the routine's message is taken back with `message.deleted`) and notifies no one; `routine_failed`, which fails the run with why, five in a row turning the routine off with one notice; and `pause_routine`, which pauses it and tells the person, while outside a routine run they're refused. [`flows.calx`](protocol/flows.calx) gives a routine a flow across three agents and checks each step posts in its agent's chat, as from the routine, once every step it comes after has finished, and is told what they answered and which failed; that two steps for one agent go one after the other; that a step whose inputs all failed is skipped; that a flow that loops back or names an agent that isn't there is refused; that `flow.list` lists a running flow and `routine.stop` stops it; and that an agent gives a routine a flow with `schedule`. [`plugins.calx`](protocol/plugins.calx) puts plugins from the person and from an agent, checks what an agent's asks waits for the person's yes and that an allowed tool server is in new sessions, keeps a panel's data up to its limit, and deletes one from an agent once the person says yes. (protocol/queue.calx) sends to a busy agent and checks the message waits in its queue, which the person reorders, edits and drops from, goes once the turn ends, and steered, stops the turn and goes at once. A turn the person stops leaves the queue waiting, and one a restart cut short lets it go. [`tasks.calx`](protocol/tasks.calx) starts tasks and checks each runs in a conversation of its own while the chat stays free, ends done with the agent's answer, pauses and resumes, is cancelled and tried again, fails with why, is started by an agent with `start_task`, and carries on after a restart. [`control.calx`](protocol/control.calx) has an agent list loom's commands and run them with `run_command`: a conversation, a shared note and an agent that asks first go at once and are in the activity log, a secret, the account, loosening its own mode and deleting itself are refused, a looser mode for another than its own is refused, one within its own and removing an MCP server ask the person, `user.list` runs as the device that said yes, and `acp.registry`'s later answer reaches the agent. An agent gives the command that installs loom on a new server, and adding one to the app asks the person, whose yes offers it to the device that gave it (`server.offered`). [`link_codes.calx`](protocol/link_codes.calx) sets a new server up with a link code: the setup code gives one, one at a time, for 15 minutes, and `loom link` too; an agent's `add_server` passes it on, the core of the device that said yes says `core.offer`, and a real core for the new server signs in with it, which makes the owner with the person's username and no password, so no login works until `password.set`. On a server set up already, `loom link` and an owner's `link.create` for someone sign in to that account, while a member can't make one for someone else. A used, replaced, expired or another instance's code is refused, and too many wrong ones are rate limited. `loom import` with no token makes itself one that only imports, for 15 minutes, uses it and drops it. [`asks.calx`](protocol/asks.calx) has agents ask agents: an ask carries its task, bounds and a good answer under headings, one with nothing in it is refused, a chain of four asks goes through and a fifth is refused, an ask back to an agent already in the chain is refused, and the next ask after a chain ends starts a new one. [`record.calx`](protocol/record.calx) has the fake agent act and checks each action is recorded before it happens and marked done, failed or refused with its rule: a tool call of loom's, a command one, one the person says no to, and the agent's own tool calls. A call that only reads isn't recorded, the person's secrets and a password show only as their length in every entry, and `activity.export` gives the log as CSV. [`handoff.calx`](protocol/handoff.calx) checks a session is told the folder the person's agents share, that `message_agent` hands over a file from the agent's own folder or that one and the other agent gets it as an attachment, kept as the person's file, and that a file outside both, or one that isn't there, isn't handed over. [`models.calx`](protocol/models.calx) checks an agent gets what its program offers as `options`, that a model and effort the person picks are set in the session before its next prompt, that one it doesn't offer is refused, and that `""` takes an option back to what a new session starts on. [`defaults.calx`](protocol/defaults.calx) puts the person's agent defaults and checks every device hears them, that a new agent runs on the default brain and follows the rest, that its session starts on the default model and effort and is told the instructions for every agent once, and again when they change, that its own pick wins until `null` takes it back, that a default its program doesn't offer is passed over, that an agent with no permission mode of its own works in the default's while one with its own keeps it, that an agent reads the defaults at once but changing them asks the person, and that with the default `steer` a message to a busy agent steers, unless the agent's own `busy` says queue. [`backup_brain.calx`](protocol/backup_brain.calx) gives the person's defaults and an agent a backup program, refusing one that isn't installed, and checks an agent whose program runs out of usage has its turn answered by the backup, in the same reply, which says so first in a `notice`, that the chat moves there with `conversation.updated` and stays, and that `conversation.move` puts it on another program, refused while a turn runs, whose first turn says it moved and starts with loom's summary of the chat, once. An agent whose backup is `none` fails the turn, saying why, and one whose program doesn't start goes to its own backup. [`rules.calx`](protocol/rules.calx) puts rules on a command, a site, a path, loom's tools, an effect and who started the turn, for every agent and for one, refuses one with nothing to match or a starter that isn't one, and checks every device hears them, in words; that `rule.check` says a deny rule wins past a mode that allows everything, chained or not, an allow rule only when every chained command matches, a site rule takes the hosts under it, and with no rule the mode decides; that the fake agent's command a rule denies is denied without asking, naming the rule in the activity log, a fetch a rule asks about asks with no always, and an allow answers by itself; that one of loom's own tools a rule denies is refused and one it asks about runs once the person says yes; that an agent asks a what-if at once but removing a rule asks; that a change keeps what it doesn't name; and that another account sees none of them.  [`summary.calx`](protocol/summary.calx) checks `agent.summary` counts an agent's own notes, the person's skills, its tables, the files in its folder with their size, its routines and the tokens its runs used. [`mentions.calx`](protocol/mentions.calx) checks a file a reply names in `code` comes with it as a mention when it's in the agent's folder, and not when it isn't there or is outside, and that `agent.file` keeps it as the person's file and refuses one outside. [`flow_restart.calx`](protocol/flow_restart.calx) restarts the instance while a step of a routine's flow is running, and checks the step goes again and the flow finishes. [`threads.calx`](protocol/threads.calx) gives a routine a thread of its own and checks its runs post there, in a conversation marked with the routine, the next one into the same thread, while a routine that posts into the chat still finds the chat; that an agent makes one with `schedule`; and that a `post` that's neither is refused. [`side.calx`](protocol/side.calx) asks side questions and checks the agent answers with the chat to go on, in a conversation of its own for them marked `side`, with nothing added to the chat, that a tool that asks is refused there without asking the person, and that the next question goes to the same conversation. [`pins.calx`](protocol/pins.calx) pins messages and checks every device hears it, with who pinned it, that `messages.pinned` lists them newest first, that unpinning takes one off, and that an agent pins one too. Then it pins an agent, which keeps when, isn't a revision, stays pinned when the agent changes, and comes off again. [`branch.calx`](protocol/branch.calx) branches a chat at a message and checks the branch is marked with where it came from, that the agent's first turn there has the chat up to that message and not after it, while the chat goes on as it was, that a message that isn't there or one in the side questions is refused, and that an agent branches one too. [`browser.calx`](protocol/browser.calx), with a Chrome, Edge or Chromium on the computer, has the fake agent open a page, read its outline, type, click, go back and take a picture, fill secrets it never reads, and have the person watch and take over; `html_preview` gives a picture of a page and what its console said, of the whole page too, while the agent's own page stays as it was. Without a browser it says it was skipped. [`teach.calx`](protocol/teach.calx) has the fake agent propose a skill and a note, which wait for the person and which the agent can't keep itself; a kept note is the agent's, tied to its site, a kept skill has what the person changed, a dropped one is never kept, and `proposal.ask` starts a task with the chat in it. With a browser, a note tied to a site is shown to the agent when its browser opens a page there, once a visit; the person takes over and records a task, whose steps keep the pages, the clicks and what was typed but not what went into a password field or any of their secrets; the agent's write-up task is given the steps, and its `save_skill` there is proposed, with the steps, until the person keeps it. Without a browser that part says it was skipped. [`pages.calx`](protocol/pages.calx) has `html_render` put a page in the agent's reply as a `text/html` file block, kept as the person's file as it was given, refuses an empty one, and checks the activity log says so, and that with the agent in two chats the page goes in the one that made it. [`cards.calx`](protocol/cards.calx) has `show_card` put cards in the agent's reply, tidied and with their ids, refuses one that can't be drawn or a type there isn't, sends each new or changed card at once as a `card` frame in its block's place, keeps the last of each in the finished reply, and refuses to change a card from another reply. [`tables.calx`](protocol/tables.calx) has one agent make a shared table, which it owns, and another write to it: what the other wrote reads as untrusted, `where`, `order_by` and `limit` pick rows, the other can't change or delete the owner's rows but changes its own, the owner deletes any, the person reads and writes from the app, and `drop_table` asks the person first. [`scripts.calx`](protocol/scripts.calx) turns scripts on and checks a script asks an agent by name and gets its answer, in the agent's chat as from a script; that a proxy's or the phones' bridge's headers, or a wrong token, are refused; that it lists and answers what waits for the person, and runs a routine by name; that `loom ask` and `loom approvals` do the same from the command line, and say how to get a token without one; that an agent can't turn scripts on; and that `scripts.off` ends the token. [`backup.calx`](protocol/backup.calx) exports a running instance, imports it into a new folder and starts there, and checks the same token sees its agents, conversations, files and secrets. [`move.calx`](protocol/move.calx) moves an instance to a `loom receive` with an app connected: only the owner can, an agent asks first, and a wrong code moves nothing. The app gets a moved frame signed with the key `welcome` gave it, the old place keeps saying where it went, and the new place takes the same token from the same event number, with the same key and everything there. [`noise.calx`](protocol/noise.calx) turns phones on and checks the network port takes only `/ws/noise`, that a handshake against another key goes nowhere, and that a phone with the key from `link.create` joins, says hello, and sends and fetches a file bigger than one Noise message through the one socket. Phones stay on across a restart, on the same port with the same key, and turning them off closes the socket. [`sandbox.calx`](protocol/sandbox.calx), with Podman and pasta on Linux, builds an image with `loom` and the fake agent and runs a member's agent in her sandbox: it gets her own secrets but not the owner's program settings, has its home in her folder whatever folder it names, reaches loom's tools through the gate, and a file it links to is read in the sandbox, so the instance's database isn't. Then the owner shares the program's settings with 100 tokens a day: her agent gets them, a turn that reports 150 tokens leaves her none, `acp.list` says so, her next run finishes `limit`, and with her own key as a secret she's past no budget and her key wins. Her agent with a list of hosts runs in a sandbox of its own with no network, reaches nothing straight, a host on its list through its egress but no other, and loom's tools; an empty list lets nothing out from its next connection, and opening its network back up takes its sandbox away. The owner's agent marked isolated runs in the owner's sandbox, on the owner's own settings. Removing her removes the sandboxes and the folder. Elsewhere it says it was skipped. [`isolated.calx`](protocol/isolated.calx) checks, on an instance without sandboxes, that isolating an agent or giving it a network is refused (`not_here`) rather than pretended, that a network without isolation and a host that isn't one are refused, that `acp.list` says there are no sandboxes, and that a member's agents are always isolated and can't be made otherwise. [`egress.calx`](protocol/egress.calx) runs `loom egress` through a stand-in for the container runtime ([`fake_runtime`](fake_runtime/main.calx)), on any computer, and checks loom's tools go on to the gate, a host not on the list is refused saying what is, so is one on the list that's on the server itself, a new list holds at once, a host on the list is reached (where this computer reaches it), the browser's way out is held to the same list and doesn't reach loom's tools, and closing the instance's end ends it. [`people.calx`](protocol/people.calx) has the owner invite someone, who joins once with a one-use invite, while a wrong code, a taken username and a weak password are refused. A member can't invite or list people, an admin invites members but not admins, a person deletes their own account but the owner can't, someone removed loses their session and token, and a member's agent doesn't run on an instance without sandboxes. The owner gives an agent program to only some people, so a member without it doesn't see it in `acp.list`, can't make an agent on it, and her agent already on it finishes `failed` with why; shares its settings with only some, which a new budget keeps; and gives it back to everyone. Real cores give the invite and reset links, a new core joins from one, and a reset link sets a new password once; `loom user password` resets the owner's and signs their devices out. The people log keeps all of it, with who did it, past their going, a page at a time, for owners and admins only, who hear of each entry as it comes. [`push.calx`](protocol/push.calx) registers a phone's APNs token, refuses one that isn't, and sets up the APNs key from the command line, kept only sealed. Then, against a fake APNs, it checks a reply comes to the phone when the person is on none of their devices, a question with Allow and Deny and a notify come to a phone that isn't connected, each with a provider token signed with the key, a connected phone gets none, and a token APNs calls gone gets no more. [`update.calx`](protocol/update.calx) serves releases from a folder and checks the updater takes a signed one and refuses one signed with another key, or with a file that isn't the one named, and that a look on the timer at a manifest that didn't change reads nothing more while the next one after a release finds it. [`core_update.calx`](protocol/core_update.calx) runs a core with the hub against an instance run by hand with a release of its own: the core asks who may update it, lists it in `core.updates`, updates everything, sees the instance restart, and is back on the new version by itself; an instance that says it's in Docker is listed with why, and left alone. [`server_update.calx`](protocol/server_update.calx) builds loom, makes newer copies of it by changing the version in the program, and serves them as signed releases with a key of its own (`--test-release`): the instance says its version, refuses a member and a release signed with another key, waits for a turn before it restarts as the new program on the same port, stops one with `now` and carries its task on after, and with self-updates on, updates once it's quiet and tells its owner. [`imports.calx`](protocol/imports.calx) makes a small OpenBot data folder and a Grok Bot one of its own, with secrets beside them, and checks `import.scan` finds them, and says which endpoint OpenBot's Claude uses but never its token, and `import.run` brings each kind over with its own times, none of the secrets, and nothing twice the second time, only for the owner, and from `loom import` too. With `carry_provider` the endpoint and token go into the Claude program's sealed settings, and an agent on it starts with that endpoint. `loom import openbot --from-user` (with `--test-from-home`, for a home folder of its own) stages a snapshot of a database OpenBot is still writing to, with what's only in its WAL, the chats' files but no secret and the user's skills, the instance imports it for its owner, and the staged token is gone afterwards.
  [`version.calx`](protocol/version.calx) checks `GET /api/version` answers with no token, before setup and after. [`code.calx`](protocol/code.calx) has an agent in Code Mode, whose session gets only `loom mcp`, with `search_tools` and `run_code`, and `add_server` and the device tools called directly beside them while the session's tools stay the same: it finds loom's tools and the fake MCP server's as TypeScript signatures, and runs scripts in a Deno the instance fetched, which call both, while the script has no environment, files, programs or network and the server's secret never reaches it. A call its permission mode doesn't allow waits for the person, a yes lets the script go on and a no throws in it, and the call is in the activity log. A script that throws gives the line of its code, and one that runs too long, calls too often or says too much is stopped, refused or cut. Turned off, the chat's next message goes to a fresh session that's told its tools changed, and the agent gets every tool plainly again. Where Deno can't be fetched, the scripts are skipped, and it says so. [`../kit.calx`](kit.calx) has what they share: starting an instance with the fake agent, and removing its folder when it stops, HTTP calls, and an app's session.
- **End-to-end tests:** the real apps against an instance with the fake agent. [`setup/e2e.calx`](setup/e2e.calx), on Windows, builds loom's installer with a test key and, in a folder of its own, installs, rolls back an update whose loom can't start, updates, refuses a setup signed with another key, uninstalls, and has v0.1's updater hand over to the setup; elsewhere it says it was skipped.
- **Benchmarks** ([`bench/`](bench/)), run by hand, not by `check.calx`. [`chat.calx`](bench/chat.calx) builds the server with `--release`, starts it with the fake agent, and times a long reply streamed a word a delta, short turns (to the ack, the first word and the end), a new device catching up on all of it, a page of the chat, and a real core catching up into its cache, with the server's CPU and memory: `calx run --release tests/bench/chat.calx -- 10000 1000`. [`desktop.calx`](bench/desktop.calx) makes a data folder with a long chat for the desktop app built with `--features perf` (desktop/README.md, "Measuring"), and streams a reply into it while the app runs.

Unit tests live beside the code, as `@test` functions run with `calx test`. `calx scripts/check.calx` runs them all.
