# tests

- **The fake ACP agent** ([`fake_agent/main.calx`](fake_agent/main.calx)): a Calx program that speaks ACP over stdio, as `claude-agent-acp` does, and plays the turn its prompt spells out, one step a line: text to say, `/think`, `/plan`, `/tool`, `/ask` (a tool call that asks permission), `/slow` and `/sleep`, `/stop` with a stop reason, `/fail` and `/crash`, `/files` (says what files came with the prompt) and `/image` (sends a small PNG back). So sessions, approvals, cancelling and crashes are tested without a real model. The comment at its top lists every step. Run it with `calx tests/fake_agent/main.calx`.
- **Protocol tests** ([`protocol/`](protocol/)): Calx scripts that drive a real instance through HTTP and the WebSocket, as an app would. [`phase1.calx`](protocol/phase1.calx) sets up the owner, adds a second account, chats with the fake agent, drops the connection in the middle of a reply and catches up, answers an approval, cancels a run, and checks the second account sees none of it. With `LOOM_TEST_CLAUDE="npx -y @agentclientprotocol/claude-agent-acp"` set, it also chats with Claude.
  [`files.calx`](protocol/files.calx) sends files up and back, checks only their owner can read them and that images get thumbnails, sends them to the agent and takes an image back, searches, and holds the storage limit. [`core_conn.calx`](protocol/core_conn.calx) and [`local.calx`](protocol/local.calx) test the core's connection and the instance in the desktop app, whose QR code, with phones on, names the computer over Noise at its addresses on the network; the first also has a second core join by the QR code the first shows, once. [`core_noise.calx`](protocol/core_noise.calx) has a real core join an instance in the desktop app over Noise from a QR code with a `noise://` place, past an address that answers nothing, then connect and send and fetch a file; a place with another key is unreachable. The instance says where it is with mDNS, under its Noise key, and a relay whose only address answers nothing finds it that way and gets through. [`core_move.calx`](protocol/core_move.calx) has a core follow its instance to a new place, once the new place answers with the same key. [`tools.calx`](protocol/tools.calx) has the fake agent call loom's own tools through `loom mcp`: one agent hands work to another, edits its instructions, makes agents and sends a notification, and deleting or changing a permission mode waits for the person's yes, while a looser one than the agent's own is refused. Agents remember notes, recall them by their words, and read the shared ones of other agents. [`registry.calx`](protocol/registry.calx) serves an ACP Registry from a folder, with the fake agent built and zipped as a binary release, installs it with a setting, runs an agent on it, and checks a wrong SHA-256, an agent with no build here, and a member are refused. [`sessions.calx`](protocol/sessions.calx) restarts the instance and checks each conversation picks its ACP session up again, with `session/load` or `session/resume`, or starts a new one. [`events.calx`](protocol/events.calx) prunes events and checks a device from before what's left, or a new one, gets a snapshot. [`servers.calx`](protocol/servers.calx) sets up MCP servers and a secret, and checks an agent's session gets the ones it has, with the secret filled in, and the database keeps it only sealed. [`devices.calx`](protocol/devices.calx) runs a real core as a PC that offers tools, and checks an agent reads a file there, is refused a tool that's off, and runs a command only once the PC itself says yes. [`routines.calx`](protocol/routines.calx) runs routines with a minute that lasts 100 ms, and checks they post into their agent's chat on schedule and notify, that daily and weekday ones run next at their time in their time zone, pause, run by hand, are made and deleted by agents with the person's yes, and catch up after a restart or not, as each says. [`webhooks.calx`](protocol/webhooks.calx) runs a routine from its webhook, signed as GitHub signs and with a bearer secret, checks its agent gets what was posted, and that a wrong secret, a forged signature, a paused routine and an unknown hook are turned away. [`quiet.calx`](protocol/quiet.calx) has routine runs call `routine_quiet`, which leaves nothing in the chat (the routine's message is taken back with `message.deleted`) and notifies no one; `routine_failed`, which fails the run with why, five in a row turning the routine off with one notice; and `pause_routine`, which pauses it and tells the person, while outside a routine run they're refused. [`flows.calx`](protocol/flows.calx) gives a routine a flow across three agents and checks each step posts in its agent's chat, as from the routine, once every step it comes after has finished, and is told what they answered and which failed; that two steps for one agent go one after the other; that a step whose inputs all failed is skipped; that a flow that loops back or names an agent that isn't there is refused; that `flow.list` lists a running flow and `routine.stop` stops it; and that an agent gives a routine a flow with `schedule`. [`plugins.calx`](protocol/plugins.calx) puts plugins from the person and from an agent, checks what an agent's asks waits for the person's yes and that an allowed tool server is in new sessions, keeps a panel's data up to its limit, and deletes one from an agent once the person says yes. (protocol/queue.calx) sends to a busy agent and checks the message waits in its queue, which the person reorders, edits and drops from, goes once the turn ends, and steered, stops the turn and goes at once. A turn the person stops leaves the queue waiting, and one a restart cut short lets it go. [`tasks.calx`](protocol/tasks.calx) starts tasks and checks each runs in a conversation of its own while the chat stays free, ends done with the agent's answer, pauses and resumes, is cancelled and tried again, fails with why, is started by an agent with `start_task`, and carries on after a restart. [`control.calx`](protocol/control.calx) has an agent list loom's commands and run them with `run_command`: a conversation, a shared note and an agent that asks first go at once and are in the activity log, a secret, the account, loosening its own mode and deleting itself are refused, a looser mode for another than its own is refused, one within its own and removing an MCP server ask the person, `user.list` runs as the device that said yes, and `acp.registry`'s later answer reaches the agent. An agent gives the command that installs loom on a new server, and adding one to the app asks the person, whose yes offers it to the device that gave it (`server.offered`). [`asks.calx`](protocol/asks.calx) has agents ask agents: an ask carries its task, bounds and a good answer under headings, one with nothing in it is refused, a chain of four asks goes through and a fifth is refused, an ask back to an agent already in the chain is refused, and the next ask after a chain ends starts a new one. [`record.calx`](protocol/record.calx) has the fake agent act and checks each action is recorded before it happens and marked done, failed or refused with its rule: a tool call of loom's, a command one, one the person says no to, and the agent's own tool calls. A call that only reads isn't recorded, the person's secrets and a password show only as their length in every entry, and `activity.export` gives the log as CSV. [`handoff.calx`](protocol/handoff.calx) checks a session is told the folder the person's agents share, that `message_agent` hands over a file from the agent's own folder or that one and the other agent gets it as an attachment, kept as the person's file, and that a file outside both, or one that isn't there, isn't handed over. [`flow_restart.calx`](protocol/flow_restart.calx) restarts the instance while a step of a routine's flow is running, and checks the step goes again and the flow finishes. [`threads.calx`](protocol/threads.calx) gives a routine a thread of its own and checks its runs post there, in a conversation marked with the routine, the next one into the same thread, while a routine that posts into the chat still finds the chat; that an agent makes one with `schedule`; and that a `post` that's neither is refused. [`side.calx`](protocol/side.calx) asks side questions and checks the agent answers with the chat to go on, in a conversation of its own for them marked `side`, with nothing added to the chat, that a tool that asks is refused there without asking the person, and that the next question goes to the same conversation. [`pins.calx`](protocol/pins.calx) pins messages and checks every device hears it, with who pinned it, that `messages.pinned` lists them newest first, that unpinning takes one off, and that an agent pins one too. [`branch.calx`](protocol/branch.calx) branches a chat at a message and checks the branch is marked with where it came from, that the agent's first turn there has the chat up to that message and not after it, while the chat goes on as it was, that a message that isn't there or one in the side questions is refused, and that an agent branches one too. [`browser.calx`](protocol/browser.calx), with a Chrome, Edge or Chromium on the computer, has the fake agent open a page, read its outline, type, click, go back and take a picture, fill secrets it never reads, and have the person watch and take over; `html_preview` gives a picture of a page and what its console said, of the whole page too, while the agent's own page stays as it was. Without a browser it says it was skipped. [`pages.calx`](protocol/pages.calx) has `html_render` put a page in the agent's reply as a `text/html` file block, kept as the person's file as it was given, refuses an empty one, and checks the activity log says so, and that with the agent in two chats the page goes in the one that made it. [`tables.calx`](protocol/tables.calx) has one agent make a shared table, which it owns, and another write to it: what the other wrote reads as untrusted, `where`, `order_by` and `limit` pick rows, the other can't change or delete the owner's rows but changes its own, the owner deletes any, the person reads and writes from the app, and `drop_table` asks the person first. [`scripts.calx`](protocol/scripts.calx) turns scripts on and checks a script asks an agent by name and gets its answer, in the agent's chat as from a script; that a proxy's or the phones' bridge's headers, or a wrong token, are refused; that it lists and answers what waits for the person, and runs a routine by name; that `loom ask` and `loom approvals` do the same from the command line, and say how to get a token without one; that an agent can't turn scripts on; and that `scripts.off` ends the token. [`backup.calx`](protocol/backup.calx) exports a running instance, imports it into a new folder and starts there, and checks the same token sees its agents, conversations, files and secrets. [`move.calx`](protocol/move.calx) moves an instance to a `loom receive` with an app connected: only the owner can, an agent asks first, and a wrong code moves nothing. The app gets a moved frame signed with the key `welcome` gave it, the old place keeps saying where it went, and the new place takes the same token from the same event number, with the same key and everything there. [`noise.calx`](protocol/noise.calx) turns phones on and checks the network port takes only `/ws/noise`, that a handshake against another key goes nowhere, and that a phone with the key from `link.create` joins, says hello, and sends and fetches a file bigger than one Noise message through the one socket. Phones stay on across a restart, on the same port with the same key, and turning them off closes the socket. [`sandbox.calx`](protocol/sandbox.calx), with Podman and pasta on Linux, builds an image with `loom` and the fake agent and runs a member's agent in her sandbox: it gets her own secrets but not the owner's program settings, has its home in her folder whatever folder it names, reaches loom's tools through the gate, and a file it links to is read in the sandbox, so the instance's database isn't. Then the owner shares the program's settings with 100 tokens a day: her agent gets them, a turn that reports 150 tokens leaves her none, `acp.list` says so, her next run finishes `limit`, and with her own key as a secret she's past no budget and her key wins. Removing her removes the sandbox and the folder. Elsewhere it says it was skipped. [`people.calx`](protocol/people.calx) has the owner invite someone, who joins once with a one-use invite, while a wrong code, a taken username and a weak password are refused. A member can't invite or list people, an admin invites members but not admins, a person deletes their own account but the owner can't, someone removed loses their session and token, and a member's agent doesn't run on an instance without sandboxes. Real cores give the invite and reset links, a new core joins from one, and a reset link sets a new password once; `loom user password` resets the owner's and signs their devices out. The people log keeps all of it, with who did it, past their going, a page at a time, for owners and admins only, who hear of each entry as it comes. [`push.calx`](protocol/push.calx) registers a phone's APNs token, refuses one that isn't, and sets up the APNs key from the command line, kept only sealed. Then, against a fake APNs, it checks a reply comes to the phone when the person is on none of their devices, a question with Allow and Deny and a notify come to a phone that isn't connected, each with a provider token signed with the key, a connected phone gets none, and a token APNs calls gone gets no more. [`update.calx`](protocol/update.calx) serves releases from a folder and checks the updater takes a signed one and refuses one signed with another key, or with a file that isn't the one named. [`../kit.calx`](kit.calx) has what they share: starting an instance with the fake agent, HTTP calls, and an app's session.
- **End-to-end tests:** the real apps against an instance with the fake agent.

Unit tests live beside the code, as `@test` functions run with `calx test`. `calx scripts/check.calx` runs them all.
